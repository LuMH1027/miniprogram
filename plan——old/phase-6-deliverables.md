## 4. 回滚预案

### 快速回滚

1. 恢复上一稳定版本的小程序代码包。
2. 保留订单表新增 `remark` 字段，不需要删除；旧版本忽略该字段即可。
3. 若支付异常，优先关闭线上发布并回到商城原链路。
4. 若非目标入口隐藏误伤主链路，回滚 `utils/routeGuard.js` 引用和 Tab 配置。

### 分模块回滚建议

| 模块 | 回滚方式 |
| --- | --- |
| Tab 精简 | 回滚 `app.json`、`custom-tab-bar/data.js` |
| 菜品文案 | 回滚显示层文案，不改底层表 |
| 订单备注 | 停止传 `remark`，保留字段 |
| 支付加固 | 回滚 `expectedStatus` 与跳转策略，但保留支付 SDK 调用 |
| 非目标入口兜底 | 移除页面 `redirectUnavailableFeature` 调用 |

| 风险 | 等级 | 规避策略 |

## 6. 灰度发布步骤

1. 在开发版打开 mock，跑通本地演示链路。
2. 切到真实后端和支付沙箱，小额支付验证。
3. 上传体验版，邀请内部用户灰度。
4. 观察关键指标：下单成功率、支付成功率、待付款重试率、订单状态异常数、备注空值比例。
5. 灰度无 P0/P1 问题后提交审核。
6. 审核通过后小流量发布，观察至少 24 小时。
