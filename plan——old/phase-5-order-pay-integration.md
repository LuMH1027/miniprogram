# 第五阶段：联调下单和支付流程

## 1. 阶段目标
- 完成点单车下单到微信支付再到订单状态更新的稳定闭环。

## 2. 开发内容
- 串联点单车、订单创建、支付调起、支付回调、订单状态更新。
- 增强异常场景处理：支付失败、取消支付、重复点击。

## 3. 涉及模块
- pages/cart
- pages/order/order-confirm
- services/order/order.js
- services/order/orderItem.js
- services/pay/pay.js
- 支付云函数与订单状态更新逻辑

## 4. 详细任务步骤
1. 下单链路联调
- 校验点单车数据转订单参数完整性。
- 校验订单项创建和金额计算一致。

2. 支付链路联调
- 校验支付参数生成、签名、唤起支付流程。
- 校验支付成功后状态流转。

3. 异常分支处理
- 支付取消保持待支付状态。
- 支付失败可重试并避免重复创建订单。

4. 幂等与防重
- 提交订单按钮增加防重控制。
- 支付回调状态更新增加幂等保护。

5. 监控与日志
- 增加关键节点日志（下单、支付调起、回调、状态更新）。
- 增加失败原因归类统计。

6. 业务验收
- 跑通全流程脚本与人工场景。
- 对比订单金额、状态、备注是否一致。

## 5. 测试重点
- 正常支付场景。
- 取消支付场景。
- 支付失败重试场景。
- 网络抖动与重复提交场景。

## 6. 注意事项
- 支付核心代码最小改动。
- 禁止在联调阶段引入新的业务分支。
- 先保证稳定，再做体验优化。

## 7. 交付物
- 联调记录与问题清单
- 支付异常处理策略文档
- 状态流转校验报告

## 8. 完成标准
- 下单支付主链路成功率达到预期。
- 订单状态与金额数据一致，无重复单和脏状态。
