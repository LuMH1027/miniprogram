# 第三阶段：改造商品为菜品

## 1. 阶段目标
- 完成商品语义向菜品语义的统一改造。
- 保障展示、分类、加车、规格选择等核心体验连续。

## 2. 开发内容
- 全量文案替换：商品 -> 菜品，购物车 -> 点单车。
- 菜品列表与详情展示字段映射优化。
- 规格选择语义改造（规格、口味、份量等）。

## 3. 涉及模块
- pages/home
- pages/goods/category
- pages/goods/list
- pages/goods/details
- pages/cart
- components/goods-card、components/goods-list、components/filter
- services/good、services/sku
- model/good、model/cart

## 4. 详细任务步骤
1. 术语替换与文案统一
- 统一页面标题、按钮文案、提示文案。
- 统一日志和埋点事件中的业务命名。

2. 数据映射层改造
- 在服务层增加菜品映射转换，减少页面改动面。
- 对字段缺失场景给默认值，避免渲染异常。

3. 列表与详情体验对齐
- 菜品卡片信息精简：名称、价格、月售或基础标签。
- 详情页保留必要信息，移除商城化营销区块。

4. 点单车语义适配
- 将购物车文案与操作提示统一改成点单场景。
- 保持数量加减、删除、结算逻辑不变。

5. 联调与回归
- 校验列表加车、详情加车、点单车数据一致。
- 校验规格选择与价格计算一致。

## 5. 测试重点
- 菜品列表加载与分页。
- 规格选择后价格和数量计算。
- 点单车和详情页数据同步。

## 6. 注意事项
- 不强制重命名底层表结构，优先映射兼容。
- 保留原接口签名，避免影响其他页面调用。
- 先改显示层，再逐步清理内部命名。

## 7. 交付物
- 菜品语义统一文案包
- 字段映射说明文档
- 点单车交互改造清单

## 8. 完成标准
- 用户感知层面已经是外卖菜品点单，而非电商商品购买。
- 不出现语义混乱或关键文案遗漏。
