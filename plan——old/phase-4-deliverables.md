# 第四阶段交付物：订单备注能力

## 1. 备注字段接口契约

### 创建订单

`services/order/order.js`

```js
createOrder({
  status: ORDER_STATUS.TO_PAY,
  addressId: userAddress._id,
  remark: '少辣，不要香菜',
});
```

| 字段 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `remark` | `String` | 否 | `''` | 订单级用户备注，建议 0-200 字 |

兼容策略：

- 旧调用方不传 `remark` 时自动按空字符串处理。
- 历史订单没有 `remark` 字段时，前端统一显示“无备注”。
- 备注不参与订单状态判断，不影响支付链路。

### 查询订单

订单列表与订单详情沿用现有接口返回结构，新增透传字段：

```js
{
  _id: 'orderId',
  status: 'TO_PAY',
  remark: '少辣，不要香菜'
}
```

前端展示：

- 订单列表：展示两行摘要。
- 订单详情：展示完整备注。
- 空备注：显示“无备注”。

## 2. 输入校验与清洗

订单确认页新增 `sanitizeRemark`：

| 规则 | 处理 |
| --- | --- |
| 最大长度 | 200 字 |
| 尖括号 | 移除 `<`、`>` |
| 控制字符 | 移除不可见控制字符 |
| 前后空白 | `trim()` |

小程序 WXML 本身会对文本插值转义，以上清洗作为额外防护，降低脚本内容或异常字符进入订单数据的风险。

## 3. 前端改动范围

| 模块 | 改动 |
| --- | --- |
| `pages/order/order-confirm` | 新增订单备注输入框、字数统计、提交时传入 `remark` |
| `services/order/order.js` | `createOrder` 增加可选 `remark` 入参，mock 和真实创建均写入 |
| `pages/order/order-list` | 订单卡片展示备注摘要 |
| `pages/order/order-detail` | 订单详情展示完整备注 |

## 4. 后台展示与筛选说明

当前仓库未包含管理后台模块。后台联动按以下契约实现：

| 场景 | 要求 |
| --- | --- |
| 订单列表 | 增加“用户备注”列，空值展示“无备注”或空白 |
| 订单详情 | 展示完整 `remark` |
| 订单搜索 | 可选支持按 `remark` 关键字搜索 |
| 订单导出 | 导出字段包含 `remark`，空值允许为空字符串 |

## 5. 测试用例

| 用例 | 输入 | 预期 |
| --- | --- | --- |
| 空备注 | 不填写 | 下单成功，列表/详情显示“无备注” |
| 普通备注 | `少辣，不要香菜` | 下单成功，列表和详情均可见 |
| 超长备注 | 超过 200 字 | 自动截断到 200 字 |
| 特殊字符 | `<script>alert(1)</script>` | 尖括号被移除，页面不执行脚本 |
| 历史订单 | 无 `remark` 字段 | 页面不报错，显示“无备注” |
| 支付失败 | 已填写备注但支付取消 | 订单仍保留备注，状态保持待付款 |

## 6. 验收结论

用户备注已从订单确认页输入，透传到订单创建，并在订单列表与订单详情展示。该能力不改变订单状态、订单项、库存扣减和微信支付调用结构。
